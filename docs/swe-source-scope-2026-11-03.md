# SWE source scope and generation policy — 3 November 2026

## Decision

Count floors had become practical stopping points: several population PRs explicitly stopped after minimums were satisfied, and no-add audits relied on aggregate primary/secondary counts. The original policy already said there were no caps. This change makes the stopping rule operational: a declared pass stays open while relevant topics are gaps or partial, regardless of minimum, preferred count or difficulty ratio. This is a process finding; it does not establish that context exhaustion caused the earlier behaviour.

## Source reconciliation

The inventory records 107 topics mapped to 41 existing canonical competencies. It preserves all 37 core/important competencies and records conditional quantitative reasoning, probability, numerical computing and applied cryptography. It does not silently change employer-evidence importance weights or require every general SWE candidate to cover every specialist topic.

Inspected six registered root READMEs plus 24 repository-owned Tech Interview Handbook topic/rubric documents. File blob SHAs and immutable source revisions are recorded in `coverage/topics/swe.yaml`. Root catalogue reconnaissance identifies topic scope; it is not an exhaustive review of all linked pages, thousands of individual questions, specialist frameworks or every employer interview. Those remain distinct ingestion/review work.

## Scope represented

- Algorithms and structures: sequences, strings, grids, intervals, hashing, linked structures, trees, tries, graphs, search/sort, recursion, DP, bit operations and distinct advanced electives.
- Programming and design: implementation quality, object/interface decomposition, patterns, runtime execution, resource ownership, text/numeric representation, bounded component construction and project/stack depth.
- System/backend: requirements, capacity estimates, availability/consistency, networking, proxy/balancing/discovery, storage models, data modelling, cache policies, queues and cloud resilience.
- Assessment and professional behaviour: coding communication, decomposition, verification, ownership, ambiguity, conflict, reflection, stakeholder alignment and influence.
- Specialist variants: frontend/browser, styling, frontend frameworks/toolchains, mobile platforms, backend frameworks, GraphQL, database/cache products, operating platforms and container/runtime choices. These are tracked as scope/technology variants under canonical competencies.
- Four existing role-plan areas retain explicit source/subtopic reconciliation gaps: observability, threat modelling, identity/access and secrets management. Existing questions are not evidence that this new source-topic mapping has been completed.

Not every source heading becomes a new competency. Resume advice, compensation, recruitment logistics, editor preferences, promotions, donation links, translated navigation and unrelated role families do not define assessed SWE competence. Specialist data-science/data-engineering, blockchain or vendor lists require their relevant role/use-case scope and independent source/content review before population. A source linking a resource does not grant its reuse rights.

## Current checkpoint

54 topics have partial, explicitly anchored question evidence; 53 have an open assessment or source-mapping gap. Zero are marked covered. These statuses are conservative review dispositions, not claims that 53 topics have absolutely no adjacent questions. Existing question IDs are retained; no question generation or lifecycle promotion is performed by this change.

For each topic, the durable inventory gives canonical mapping, general/specialist scope, source file/locator, original assessment focus, current evidence anchor and next action. An already-counted secondary tag alone cannot close a topic. Covered status requires reviewed/fully approved question evidence, an assessment anchor, topic-specific rationale and evidence spanning the mapped competencies. A justified deferral is an explicit alternative when outside a declared pass scope.

`AGENTS.md` now requires a checkpoint for each pass: inspected revisions, declared scope, topic dispositions, anchored evidence, question/no-add decisions, progression decisions, remaining gaps and next action. An unfinished run must remain marked unfinished.
